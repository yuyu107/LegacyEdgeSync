# 为什么不直接通过扩展内核运行新版 Microsoft Edge？

> LegacyEdgeSync 目前优先修复 Windows 7 上原生兼容的 Edge 109 云同步，而不是将整个新版 Edge 移植到旧系统。本篇说明技术取舍，并不否定扩展内核本身的研究价值。

## 1. 官方支持边界

微软于 2022 年 12 月宣布，**Microsoft Edge 109 是最后支持 Windows 7、Windows 8 和 Windows 8.1 的主要版本**。从 Edge 110 起，官方要求 Windows 10 或更新系统。

- [Microsoft Edge 官方公告](https://blogs.windows.com/msedgedev/2022/12/09/microsoft-edge-and-webview2-ending-support-for-windows-7-and-windows-8-8-1/)
- [Microsoft Edge 支持的操作系统](https://learn.microsoft.com/zh-cn/deployedge/microsoft-edge-supported-operating-systems)

## 2. 为什么扩展内核不是本项目目前的主要路线？

扩展内核或兼容层可以在一定程度上解决旧系统缺少 API、程序版本检查等问题。不过，**新版 Edge 启动成功不等于可稳定使用**。现代 Chromium 浏览器有浏览器、渲染器、网络、GPU 等多个进程，还涉及沙盒隔离、驱动、图形与媒体、账户验证等功能。

| 组成部分 | 需要验证的兼容性风险 |
| --- | --- |
| 安装、更新 | 系统版本检测、服务和更新逻辑 |
| 多进程与系统 API | 不同子进程可能依赖不同的系统能力 |
| 浏览器沙盒 | 进程隔离和安全策略可能不兼容 |
| GPU、图形、媒体 | 驱动和硬件加速行为可能异常 |
| 微软账户、在线服务 | 能登录不代表同步、头像等功能都正常 |
| 后续新版 | 更新可能引入新依赖，增加维护负担 |

以上是技术风险和研究成本的分析，**不是声称我们已经逐一复现新版 Edge 在某个特定扩展内核上的全部问题**。不同扩展内核和 Edge 构建的兼容能力，需要分别验证。为了启动浏览器而关闭沙盒或削弱安全防护，不宜作为面向一般用户的解决方案。

## 3. 为什么选择修复 Edge 109？

LegacyEdgeSync 研究的 Windows 7 SP1 x64 + Edge 109.0.1518.140 x64 环境中，浏览器可以运行并登录微软账户，但其云同步遇到两项明确问题：

1. 旧的同步服务发现接口在测试中返回 HTTP 404；
2. 指定可用同步地址后，服务器又返回 `UPGRADE_CLIENT`，要求更高的客户端版本。

这些障碍位于同步连接路径，而不是整个浏览器都无法启动。项目因此尝试使用启动参数与针对同步请求的运行时兼容处理，已经在测试环境观察到 Windows 7、Windows 11 间收藏夹双向同步恢复。详细经过参见 [为什么要修复同步？](WHY-SYNC-FIX.md) 与 [研究记录](RESEARCH.md)。

相对于让整个新版 Edge 运行在未经官方支持的系统上，**在原生兼容的 Edge 109 上修复一个已定位的问题，验证范围更小、定位更明确、维护更可控**。

## 4. 这不是安全性的替代方案

LegacyEdgeSync **没有真正升级 Edge**，也没有为 Edge 109 补上新版浏览器的安全修复。扩展内核方案也不应被简单理解成“获得官方兼容与支持”。如条件允许，优先使用仍受支持的 Windows 和浏览器；对于必须保留 Windows 7 的研究环境，建议使用虚拟机和测试账户，不启用密码、支付信息同步。

## 5. 今后会研究新版 Edge 吗？

可以作为独立课题，在固定 Windows、扩展内核、Edge 版本的前提下分别测试启动、渲染、网络、沙盒、账户、GPU、稳定性等。现阶段 LegacyEdgeSync 不把“所有新版 Edge 绝对不能使用扩展内核”当作结论，而是**先把已经成功的 Edge 109 同步修复做好**。
